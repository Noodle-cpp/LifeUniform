# Singularity (MCP)

Задачи проекта ведутся в **Singularity**. MCP-сервер **singularity** предоставляет **ресурсы** (чтение) и **инструменты** (в т.ч. создание задач, смена статуса и др.). Для операций с задачами использовать инструменты MCP; перед вызовом обязательно смотреть схему инструмента (параметры).

## Инструменты MCP (используемые для задач)

Вызов: `call_mcp_tool(server: "user-singularity", toolName: "...", arguments: {...})`. Идентификатор сервера в Cursor: `singularity` или `user-singularity`. Перед вызовом смотреть схему инструмента в `mcps/<server>/tools/*.json`.

### Создание и редактирование задачи

| Инструмент | Назначение | Важные параметры |
|------------|------------|-------------------|
| **createTask** | Создать задачу в проекте | `title`, `projectId` (из настроек проекта), `group` (id очереди из `singularity://task-groups`). Возвращает задачу с полем `id` (T-...). |
| **createNote** | Создать заметку | Привязка к контейнеру (задача и т.д.). У новой задачи заметка может создаваться автоматически с id вида `N-<taskId>`. |
| **updateNote** | Обновить описание (заметку) задачи | `id` — id заметки (например `N-T-...`), `containerId` — id задачи (T-...), `content` — текст (Markdown). Используется для установки/изменения описания задачи. |

### Чек-лист

| Инструмент | Назначение | Важные параметры |
|------------|------------|-------------------|
| **createChecklistItem** | Добавить пункт чек-листа к задаче | `item.parent` — **id задачи** (T-...), не id заметки. `item.title` — текст пункта. `item.done` (boolean), `item.parentOrder` (number) — по желанию. |

### Ограничения

- **Прикрепление файлов** к задаче через MCP не предусмотрено; файлы добавляются вручную в приложении Singularity.
- Смена статуса задачи (Новые / В работе / Готово) — отдельный инструмент (см. дескрипторы MCP); при вызове передавать id задачи и id статуса канбан.

## Ресурсы MCP (чтение)

Получение данных через `fetch_mcp_resource(server: "singularity", uri: "...")`:

| Ресурс | URI | Назначение |
|--------|-----|------------|
| Задачи | `singularity://tasks` | Список всех задач |
| Проекты | `singularity://projects` | Проекты |
| Статусы канбан | `singularity://kanban-statuses` | Колонки: Новые, В работе, Готово |
| Связь задача–статус | `singularity://kanban-task-statuses` | В какой колонке задача |
| Группы задач | `singularity://task-groups` | Очереди/группы |
| Заметки | `singularity://notes` | Описания (note = id заметки) |
| Пункты чек-листа | `singularity://checklist-items` | Чек-листы задач (parent = id задачи T-...) |

## Проект

- **projectId**: указать в правиле `singularity.mdc` или в .env проекта

Задачи имеют этот `projectId`; у части задач есть поле `externalId` (внешний идентификатор для импорта/интеграций).

## Статусы канбан

| Название | ID (suffix) | Назначение |
|---------|-------------|------------|
| Новые | `TODO` | Backlog / новые задачи |
| В работе | `IN-PROGRESS` | В работе |
| Готово | `DONE` | Завершённые |

Полный id статуса: `KS-{projectId}-{TODO|IN-PROGRESS|DONE}`.

## Workflow с Singularity

### Показать задачи

1. Вызвать `fetch_mcp_resource(server: "singularity", uri: "singularity://tasks")` (или инструмент списка задач, если есть).
2. Отфильтровать по `projectId` из настроек проекта.
3. При необходимости получить `singularity://kanban-task-statuses` и сопоставить задачи со статусами.
4. Вывести список: заголовок, id задачи (или externalId), статус; по запросу — детали из notes.

### Выбрать задачу для работы

1. По названию или TASK-XXX найти задачу в списке из Singularity.
2. Номер для ветки: из `title` (например TASK-007) или из `externalId` (если формат «prefix-число» — использовать число).
3. Ветка: `feature/TASK-XXX-описание`.

### Начало работы / Завершение

Создание задач и смена статуса (Новые → В работе → Готово): использовать **инструменты MCP singularity** (создание задачи, обновление, смена статуса). Перед вызовом смотреть схему инструмента. API из `.env` — запасной вариант при необходимости.

### Обновление прогресса

- **Описание задачи:** обновить через `updateNote` (id заметки = часто `N-<taskId>`, containerId = taskId, content = Markdown).
- **Чек-лист:** добавлять пункты через `createChecklistItem` с `parent` = id задачи (T-...). Редактирование/отметка выполнено — в приложении или через соответствующие инструменты MCP (см. дескрипторы).
- **Файлы:** только вручную в приложении Singularity.

## Идентификация задачи

- **id** — внутренний Singularity (например `T-02b9b3ee-8915-4219-b709-cfd500a5906d`).
- **externalId** — внешний идентификатор (например `prefix-61303761`); число можно использовать для ветки/коммита.
- **title** — например `TASK-007: Название задачи`; префикс TASK-XXX использовать для веток и коммитов.

При упоминании пользователем «TASK-007» или «задача 61303761» искать задачу по `title` или `externalId` в ресурсе tasks.
